# 教师与课程逻辑设计及规范化

本设计依据编号唯一、名称可重复、每门课程有一个学分值的业务语义推导关系模式。不能因存在自增主键就直接断言整个关系满足 3NF；必须检查所有候选键和业务函数依赖。

## 关系与数据字典

| 关系 | 字段 | 类型与约束 |
|---|---|---|
| teacher | id | BIGINT，有符号，自增主键 |
| teacher | teacher_no | VARCHAR(20)，非空、非空白、唯一 |
| teacher | name | VARCHAR(50)，非空、非空白，允许同名 |
| course | id | BIGINT，有符号，自增主键 |
| course | course_code | VARCHAR(20)，非空、非空白、唯一 |
| course | name | VARCHAR(100)，非空、非空白，允许同名 |
| course | credits | DECIMAL(4,1)，非空且大于 0 |

两张表本身没有外键。C 的 teaching_class 以 teacher_id、course_id 引用它们，ON DELETE/UPDATE RESTRICT。全局使用 InnoDB、utf8mb4。编号的唯一比较沿用数据库默认排序规则，未额外声明大小写敏感业务规则。

## 函数依赖与候选键

教师关系的依赖可写为 `id → teacher_no, name` 与 `teacher_no → id`。由传递性，teacher_no 也能决定 name。`{id}+` 和 `{teacher_no}+` 都包含全部属性，空集不能决定任何一名教师，所以两个单属性键都最小。name 不能决定编号或 id。

课程关系的依赖为 `id → course_code, name, credits` 与 `course_code → id`。因此 `{id}+`、`{course_code}+` 都是全部属性，各自为最小超键。课程名和学分都不是决定其他属性的业务标识，不能从同学分或同名样本推断依赖。

## 范式与异常

1NF：每个字段都是单个标量值，不保存教师列表或复合课程字段。2NF：所有候选键为单属性键，不存在非主属性对复合候选键真子集的部分依赖。3NF：根据上述依赖集，所有非平凡依赖的决定因素都包含某个候选键，因而是超键；两个关系均满足 3NF，且在这些已声明依赖下满足 BCNF。备用候选键之间的依赖不是应消除的非主属性传递依赖。

可以先创建尚未开课的教师和课程；删除教学班不丢失教师/课程定义；修改课程学分只需改一个课程行。重复编号被唯一约束拒绝，关联删除由外键限制，是完整性保护，不是规范化异常。

## 分解性质的推导

考虑反例宽表 `W(class_id, teacher_id, teacher_no, teacher_name, course_id, course_code, course_name, credits)`。假定一行描述一个教学班，有 `class_id → teacher_id, course_id`，`teacher_id → teacher_no, teacher_name`，`teacher_no → teacher_id`，`course_id → course_code, course_name, credits`，`course_code → course_id`。教师与课程可被多班引用，teacher_id 和 course_id 都不是 W 的超键。宽表会重复基础资料，产生更新和插入异常。

先分出 `T(teacher_id, teacher_no, teacher_name)`，余下 `W1(class_id, teacher_id, course_id, course_code, course_name, credits)`。交集是 teacher_id，且 `teacher_id → T`，满足二元分解无损判据。再将 W1 分为 `C(course_id, course_code, course_name, credits)` 与 `L(class_id, teacher_id, course_id)`，交集 course_id 且 `course_id → C`，再次无损。两次无损分解的组合可以重建原宽表中的每个班级事实；独立存在但尚未开班的教师或课程本来不属于 W 的行。

上述依赖分别完整落入 T、C、L，三者投影依赖的并集即可推出原依赖集，因此保持这些函数依赖。实际设计的 teacher、course 分别对应 T、C，L 扩展为 C 负责的教学班实体。B 的两个关系已经满足范式，无需为了展示分解而继续拆表。

## 物理索引

主键支持按 ID 查找，编号唯一索引支持编号检索及唯一校验。课程增加 `(credits DESC, course_code)`，对应按学分阈值筛选及 `ORDER BY credits DESC, course_code`；小样本上优化器仍可能选择扫描，不能声称一定更快。教师 LEFT JOIN 依赖 C 的 `(teacher_id)`，学期子查询依赖 C 的 `(semester_id, course_id)`；B 不越权重复创建 C 的索引。
