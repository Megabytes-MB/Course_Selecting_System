# 教师与课程模块需求分析

本模块为高校选课系统维护教师和课程基础资料，并提供开课查询与公共 Java 工程。教师、课程是教学班引用的独立实体。本模块成果供 C 汇总数据库报告，最终提交前仍需学生本人审核并理解。

## 用户与流程

教务人员维护教师编号、姓名、课程代码、名称和学分。教师或学生可以查询课程与开课信息。本版本没有登录和权限验证，菜单中的业务角色仅说明使用场景。典型流程为维护教师与课程、由 C 建立学期和教学班、由 A 完成学生选课与成绩，再按教师或学期查询实际开课。

## 明确需求

| 编号 | 业务规则 | 实现位置 |
|---|---|---|
| B-R01 | 教师编号唯一且必填，姓名必填 | 唯一约束、NOT NULL、CHECK 与 Java 校验 |
| B-R02 | 课程代码唯一，名称必填，学分为正精确小数 | 唯一约束、DECIMAL、CHECK 与 BigDecimal |
| B-R03 | 教师、课程均可新增、查询、修改和删除 | DAO、Service 与 CatalogMenu |
| B-R04 | 被教学班引用的基础资料不能删除 | C 的外键 RESTRICT，B 的错误提示 |
| B-R05 | 列出全部教师及其教学班，包括未开课教师 | 四表 LEFT JOIN |
| B-R06 | 按最低学分查询并稳定排序；按指定学期查询开课课程 | 条件查询与 IN 子查询 |
| B-R07 | B 提供 Maven、连接工具、主菜单及配置说明 | 公共 Java 工程 |

## 隐含需求及实施决定

查询不存在的数据返回空结果；更新与删除不存在的数据给出提示。输入中的引号作为参数值处理，不能改变 SQL 结构。中文数据必须按 UTF-8 读写，拒绝解码替换字符。删除拒绝及重复编号不应退出菜单。DAO 不擅自提交事务，调用方决定连接生命周期。

按冻结类型，学分最大 999.9。应用接受能精确表示为一位小数的正数，3.50 合法、3.55 不合法。教师同名、课程同名均允许；名称不是候选键。课程表不保存授课教师，因为同一课程的不同教学班可能由不同教师承担。

## 待团队审核及边界

共享基线 A/C 确认栏保持原状；C 需提供正式外键与教学菜单，再运行联合验收。没有增加院系、职称、学时等非必要字段；需要时由负责人依变更流程扩展。自动排课、先修课、冲突检测、鉴权、同课程多班排他均不在当前范围。
