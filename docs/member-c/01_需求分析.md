# 成员 C 需求分析：学期与教学班

教务人员先建立学期，再为已存在的课程安排授课教师、教学班和名额。学生选的是具体教学班，因此同一门课开两个班时，应分别查看各班的容量和名单；查看课程整体教学情况时，再按学期汇总各班的选课和成绩。下列规则依据集成基线 v1.0 和 C 接口文档编写，跨模块接口待三方确认。[集成基线](../../contracts/integration-baseline.md) · [C 接口文档](../../contracts/semester-teaching.md)

## 用户要完成的操作

| 操作 | 输入 | 预期结果与边界 |
|---|---|---|
| 维护学期 | 名称、起止日期；查询、修改或删除时指定学期 | 可以建立尚未开班的学期。名称必填、非空白且唯一，两个日期必填，结束日可等于开始日。已有教学班引用的学期应保留 |
| 维护教学班 | 唯一班号、学期、课程、教师、容量 | 每班对应一个学期、一门课程和一名教师。班号必填且非空白，三个引用对象均须存在。可以查询、修改班级资料；即使班内只剩退课记录，删除仍应被外键拒绝 |
| 调整名额 | 教学班、新容量 | 新容量必须为正整数，且至少等于该班当前有效选课数。教务人员应看到新的容量或明确的拒绝原因。调整失败时保留原容量。演示班 `2001–2010` 初始化时容量至少为 3 |
| 查询班级名单和人数 | 教学班或最低选课人数 | 名单列出本班有效选课学生的学号和姓名。人数只计 `ENROLLED`，按人数筛班时计入恰好达到阈值的班级。只有退课记录的班也可以列出，名单为空、人数为 0 |
| 查看学期课程统计 | 学期、课程 | 合并该组各班有效选课记录，给出选课人次、已出成绩人次、均分和及格率。同一学生在两个班均有有效选课时，每班各计一条。均分直接按已评分记录计算，及格率为其中成绩达到 60 分的比例；已出成绩数为 0 时，两项显示“暂无成绩”或返回 `NULL` |

C 负责学期、教学班和容量修改；教师与课程数据由 B 维护，学生、选退课和成绩由 A 维护。C 从 A 的选课记录读取状态和成绩。为保证并发时容量仍然有效，A 的选课事务与 C 的调容量事务都应在 `READ COMMITTED` 下先锁定同一个教学班，在持锁连接上校验并写入；写入后、提交前发生异常应回滚。[A 模块接口契约](../../contracts/student-enrollment.md) · [C 模块接口契约](../../contracts/semester-teaching.md)

## 后续验证的输入与预期

下表是设计阶段的验收样例，实际结果待正式表和服务就绪后记录。最后两行使用 A 已提交的演示选课数据。[选课初始化数据](../../database/member-a/14_seed_enrollment.sql)

| 场景 | 输入或操作 | 预期结果 |
|---|---|---|
| 学期日期边界 | 开始日为 2026-09-01，结束日分别取 2026-09-01 和 2026-08-31 | 同日允许，倒序拒绝；拒绝时不新增学期 |
| 教学班外键 | 学期、课程均存在，教师编号在测试库中不存在 | 拒绝开班，查询不到该班号 |
| 缩容边界 | 某班容量为 4，当前 2 条有效选课、1 条退课；分别把容量调为 2 和 1 | 调到 2 可成功。若接着调到 1，应拒绝，当前容量仍为 2 |
| 名单与删除 | 班 `2009` 仅有退课记录 `3009` | 名单为空、有效人数为 0；删除仍应被拒绝，原选课记录保留 |
| 空成绩、零分与及格线 | 分别检查班 `2002`、`2003`、`2006` 的有效选课 | `2002` 的成绩为 `NULL`，已出成绩 0；`2003` 的 0 分计入已出成绩，及格率 0%；`2006` 的 60 分计入及格，及格率 100% |
