# 学期与教学班的逻辑设计与规范化

本设计依据集成基线 v1.0 和 C 模块接口文档，用于后续编写 DDL。三方对共享接口的正式确认仍待完成。[集成基线](../../contracts/integration-baseline.md) · [C 模块接口契约](../../contracts/semester-teaching.md)

## 关系模式与数据字典

`semester(id, name, start_date, end_date)` 记录一个学期的名称和日期。`teaching_class(id, class_code, course_id, teacher_id, semester_id, capacity)` 记录一门课程在某学期的一次开班。以下字段均为 `NOT NULL`，所有 `BIGINT` 使用有符号类型，Java 对应 `long`。

### 学期 `semester`

| 字段 | SQL 类型 | 键与取值规则 |
|---|---|---|
| `id` | `BIGINT` | 自增主键 |
| `name` | `VARCHAR(30)` | 备用候选键，唯一，禁止空字符串和纯空白 |
| `start_date` | `DATE` | 学期开始日期 |
| `end_date` | `DATE` | 学期结束日期，`end_date >= start_date` |

### 教学班 `teaching_class`

| 字段 | SQL 类型 | 键与取值规则 |
|---|---|---|
| `id` | `BIGINT` | 自增主键，供 A 的 `enrollment.teaching_class_id` 引用 |
| `class_code` | `VARCHAR(30)` | 备用候选键，班号全局唯一，禁止空字符串和纯空白 |
| `course_id` | `BIGINT` | 外键，引用 B 的 `course.id` |
| `teacher_id` | `BIGINT` | 外键，引用 B 的 `teacher.id` |
| `semester_id` | `BIGINT` | 外键，引用 C 的 `semester.id` |
| `capacity` | `INT` | 教学班容量，`capacity > 0` |

## 函数依赖与候选键

| 关系 | 由业务规则得到的函数依赖 | 候选键的推导 |
|---|---|---|
| `semester` | `id → name, start_date, end_date` 和 `name → id` | `id` 唯一标识一行，学期名也唯一。由传递性，学期名可推出起止日期。因此 `{id}` 和 `{name}` 的属性闭包都覆盖全部四列 |
| `teaching_class` | `id → class_code, course_id, teacher_id, semester_id, capacity` 和 `class_code → id` | 一个班号对应一个教学班，因而也确定其课程、教师、学期和容量。`{id}` 与 `{class_code}` 的属性闭包都覆盖全部六列 |

以上四个候选键都只有一个属性，去掉该属性后为空集。系统允许多个学期和多个教学班，空集无法标识一行，因此这些键均为最小超键。同一门课程可在同一学期由同一教师开设多个班，三个外键的组合仍允许重复。学期起止日期也没有组合唯一的业务约定。

## 1NF 至 3NF

1. **1NF。** 每列只取一个标量值。学期起止日期分别存储，每个教学班行只关联一名教师、一门课程和一个学期。另开一班就增加一行。
2. **2NF。** 两个关系的全部候选键都是单属性键。学期的起止日期和教学班的三个外键、容量均依赖各自的完整候选键，不存在对复合候选键的部分依赖。
3. **3NF。** 按上述业务依赖，学期表中能非平凡决定其他属性的属性集必含 `id` 或 `name`，教学班表中则必含 `id` 或 `class_code`。它们均为超键。两个关系都满足 3NF，可以直接作为逻辑设计结果。

## 为什么单独存储学期

假设在一个教学班宽表中同时保存学期名和起止日期。同一学期的多行会重复这些值，调整一次结束日期就要修改多个班。此时存在 `semester_id → 学期名, 开始日期, 结束日期`，但 `semester_id` 可以关联多个班，单独不能标识宽表的一行。

将学期属性移入 `semester`，在教学班中保留 `semester_id`。将学期主键在连接时记作 `semester_id`，两个关系的公共属性就只有它，而且它能决定学期表全部属性。按二元分解的无损连接判据，用这一外键连接即可重建原有的每条教学班记录。学期标识与学期名、日期的依赖可在学期表内检查，班标识、班号与开班属性的依赖可在教学班表内检查。两个投影中的依赖合起来也能推出教学班到学期信息的传递依赖，因此该分解保持上述函数依赖。

## 参照完整性、容量与索引

- 教学班引用课程、教师和学期，选课记录引用教学班。`RESTRICT` 保护已有引用，包括仅保留退课记录的教学班。A、B、C 的主外键类型须相同。
- `capacity > 0` 可在单行检查。调容量还须满足新容量至少等于本班 `ENROLLED` 人数。这个值来自 A 的选课表，设计中由 C 的调容量事务与 A 的选退课事务在 `READ COMMITTED` 下先锁同一教学班。C 在同一连接内计数、校验并完成更新。初始化时，演示班 `2001–2010` 的容量按契约取至少 3。
- 在 `teaching_class` 上规划非唯一索引 `(semester_id, course_id)`，支持同一学期按课程查班和汇总。非唯一索引 `(teacher_id)` 支持查询教师承担的各教学班。两个索引均允许多班命中。
