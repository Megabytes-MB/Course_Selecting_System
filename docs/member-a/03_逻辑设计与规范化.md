# 成员A逻辑结构与规范化分析

## 关系模式和数据字典

Student(id, student_no, name, major)。候选键{id}与{student_no}；主键id，student_no为备用键。

Enrollment(id, student_id, teaching_class_id, status, selected_at, withdrawn_at, score)。候选键{id}与{student_id, teaching_class_id}；主键id，student_id外键指向Student.id，teaching_class_id外键指向C的TeachingClass.id。

| 表 | 字段 | 类型与空值 | 取值或约束 |
|---|---|---|---|
| student | id | BIGINT NOT NULL | 自增主键，对应Java long |
| student | student_no | VARCHAR(20) NOT NULL | 唯一、非空白 |
| student | name | VARCHAR(50) NOT NULL | 非空白，允许同名 |
| student | major | VARCHAR(100) NOT NULL | 非空白，专业名称 |
| enrollment | id | BIGINT NOT NULL | 自增主键 |
| enrollment | student_id | BIGINT NOT NULL | 外键，RESTRICT |
| enrollment | teaching_class_id | BIGINT NOT NULL | 外键，RESTRICT |
| enrollment | status | VARCHAR(10) NOT NULL | ENROLLED/WITHDRAWN，大小写敏感 |
| enrollment | selected_at | DATETIME(6) NOT NULL | 最近一次选入时间，Java LocalDateTime |
| enrollment | withdrawn_at | DATETIME(6) NULL | 最近一次退课时间，与状态关联 |
| enrollment | score | DECIMAL(5,2) NULL | 0—100，Java BigDecimal；NULL是未出成绩 |

## 函数依赖与候选键推导

Student的最小依赖覆盖可写为id→student_no、id→name、id→major、student_no→id。由传递性，student_no也决定name和major。id闭包与student_no闭包均为全部属性，且单属性键不可约。没有业务依据认为name→id、major→name或name→major成立。

Enrollment设E=id，S=student_id，T=teaching_class_id，Z={status,selected_at,withdrawn_at,score}。最小覆盖为E→S、E→T、E→Z的各个单属性右部，以及ST→E。E+和(ST)+均为全部属性；S或T各自均不能决定关系全部属性，故ST不可约。student_id不决定score，teaching_class_id也不决定score；成绩只对具体学生/教学班关系有意义。状态和时间的合法组合是行约束，不产生status→score等函数依赖。

上述依赖建立在一对学生/教学班只存一条当前关系的业务规则上。若改成保留每次选退历史，ST将不再是候选键，必须重新建模，不能沿用本结论。

## 范式判断

1NF：每列存储单个原子值，没有用逗号拼接课程列表或多个成绩；SQL可空字段采用数据库NULL，其含义已定义。

2NF：Student两个候选键均为单属性，不存在非主属性对复合候选键的部分依赖。Enrollment有单属性候选键E和复合候选键ST；非主属性status、selected_at、withdrawn_at、score依赖整组ST，没有依赖S或T的业务规则。仅“使用自增主键”不足以证明2NF，必须同时检查复合备用键。

3NF：在所声明的函数依赖及其闭包下，Student的非平凡决定因素均含id或student_no，Enrollment的非平凡决定因素均含E或ST，因此决定因素为超键，均满足BCNF，进而满足3NF。这里的判断以本版本业务依赖为限，不推断未经确认的新依赖。

## 分解依据和性质

最终两张A表已满足3NF，无需为了报告而强行分解。为展示消除冗余的推导，考虑设计阶段可能出现的U(E,S,T,student_no,name,major,status,selected_at,withdrawn_at,score)，将学生资料直接复制到每条选课记录。

由S→student_no,name,major且S不是U的超键，U存在冗余：同一学生多条选课需重复改姓名；没有选课时无法只记录学生；删除最后选课会丢失学生资料。分解为R1(S,student_no,name,major)与R2(E,S,T,status,selected_at,withdrawn_at,score)。这里R1.S映射为最终Student.id。

无损连接：两关系交集为{S}，且S→R1，满足二元分解无损连接判据。对既有选课数据可无损重建U；最终Student独立允许保存尚未选课的学生，因此其业务表达能力比只存U更完整。

依赖保持：S→学生资料、student_no→S在R1内；E→S,T,Z及ST→E在R2内。各原最小覆盖依赖都能在一个分解关系上检查，投影依赖并集可推出原依赖，故保持依赖。外键、容量、分数范围、时间规则属于其他完整性约束，不能以“保持函数依赖”代替它们的验证。

## 物理设计依据

student_no唯一索引支持精确查学号；(major,student_no)索引对应按专业筛选并按学号排序。enrollment(student_id,teaching_class_id)唯一索引阻止重复，并支持按学生查选课；(teaching_class_id,status)支持班级人数统计与名单。enrollment不复制姓名、课程名或已选人数，避免重复维护。教学班容量与实际人数是跨行约束，由共同行锁协议实现。
