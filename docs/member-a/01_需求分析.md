# 成员A需求分析

## 背景和范围

高校学生选课与成绩管理系统面向学生信息维护、教学班选退课和成绩记录。本模块管理student和enrollment，读取B的课程、C的教学班数据；采用命令行演示。用户角色是需求层面的学生、教务人员和授课教师，当前命令行版本不含登录与权限鉴别，演示者可访问全部菜单；若要求真实权限控制，应另行设计账号和授权。

## 角色与操作

学生查询个人选课明细和成绩单、选课和退课。教务人员维护学生资料、协助选退课。教师录入和修改已选学生成绩。CLI中的角色未构成安全边界，不能宣称已经实现教师仅能修改本人教学班成绩。

## 业务规则

| 编号 | 规则 | 落实方式 |
|---|---|---|
| A-R01 | 学号唯一，学号、姓名、专业不为空白 | UNIQUE、NOT NULL、CHECK及Java校验 |
| A-R02 | 学生通过选课关系关联教学班；一对组合一条记录 | 两个外键及组合唯一约束 |
| A-R03 | 状态仅ENROLLED/WITHDRAWN | CHECK及状态列区分大小写 |
| A-R04 | 仅ENROLLED计入人数，不能超过教学班容量 | 服务事务、教学班行锁、READ COMMITTED |
| A-R05 | 已选记录禁止重复选入；满员拒绝；学生和教学班必须存在 | 服务检查、唯一与外键约束 |
| A-R06 | 无成绩的已选记录才允许退课 | 事务中检查及条件UPDATE；退课保留记录 |
| A-R07 | 重新选课复用旧记录，刷新选课时间、清除退课时间 | 事务内UPDATE |
| A-R08 | 成绩可空，非空为0—100，最多两位小数 | DECIMAL、CHECK及Java BigDecimal精度校验 |
| A-R09 | 仅已选记录可录入或修改成绩，不提供清空成绩接口 | 成绩服务、统一锁规则、条件UPDATE |
| A-R10 | ENROLLED无退课时间；WITHDRAWN有退课时间、无成绩且退课不早于选课 | CHECK；时间由数据库生成 |
| A-R11 | 关联数据禁止直接删除，保留历史 | 外键RESTRICT；UI解释拒绝原因 |
| A-R12 | 失败时选退课或成绩操作整体回滚 | 单连接事务、commit/rollback、故障注入检查 |

## 流程

选课：打开独立连接 → READ COMMITTED → 开启事务 → 锁教学班 → 检查学生及现有选课 → 统计有效人数 → 检查容量 → 插入或重新激活 → 提交。任一步失败回滚。

退课：锁教学班 → 找到选课关系 → 校验已选且无成绩 → 更新状态和退课时间 → 提交。成绩录入：校验分数 → 锁教学班 → 检查已选关系 → 更新成绩 → 提交。

查询：按ID或专业查学生；按学生查询有效选课明细；成绩单仅显示有效且已出成绩记录，0分为有效成绩，空成绩表示尚未录入。

## 需求依据与待确认项

明确需求来自课程文档及三人计划：两张表、CRUD、选退课、成绩、多表查询、事务及过程记录。隐含需求：不能把未出成绩当0分；重复、满员及非法输入应给出可理解提示；并发写入必须遵守共同锁协议。

尚待三人确认：字段长度与signed BIGINT、数据库时区、删除RESTRICT、演示编号段、Java构造器注入、C的容量调整READ COMMITTED。选课期限、权限、同课程多班限制、先修课和时间冲突不在本次实现范围，不能视为已实现或已确认需求。
