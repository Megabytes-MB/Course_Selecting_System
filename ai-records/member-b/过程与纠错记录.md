## 真实错误一 非法配置路径逃出统一异常处理

初稿片段：

```java
Path path = Path.of(System.getProperty("db.config", "config/database.properties"));
try (Reader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
    config.load(reader);
} catch (IOException | IllegalArgumentException e) {
    throw new SQLException("...", "08001");
}
```

问题：Path.of 在 try 之外，含 NUL 的配置路径抛 InvalidPathException，无法遵循配置异常统一 SQLException 的契约。测试 B23 输入 Java 字符串 `"invalid\u0000path"`，实际输出为 `FAIL B23 ... actual=InvalidPathException`。这属于 AI 初稿漏掉异常边界，并非数据库自身错误。

修复：把 Path.of 与文件读取都置于外层 try，捕获 IOException/IllegalArgumentException 后生成无敏感路径的 SQLState 08001 SQLException。新空库最终重跑 B23 通过。修改位置为 app/src/main/java/edu/project/common/DBUtil.java。

## 真实错误二 将未变化更新误报为记录不存在

初稿 DAO 片段：

```java
return CatalogValues.affected(p.executeUpdate());
```

初稿菜单将 false 显示为“课程不存在”。驱动 URL 启用 useAffectedRows=true 时，记录存在但所有值相同的 UPDATE 返回零影响行，导致错误提示。B24 将 1201/CS001/数据库系统/4.0 更新为原值，实际断言失败：`existing unchanged course was reported missing`。默认驱动行为掩盖了该问题，首轮 22 项检查未覆盖这一配置分支。

修复：先检查影响行数合法性；为零时在同一连接按主键核对存在性，存在返回 true，不存在才 false。TeacherDAO、CourseDAO 同步修复。测试仍保留不存在记录更新返回 false 的 B11，避免修复后误把缺失记录当成功。

复核前实际汇总为 `22 / 24 passed`；修复后在新空测试库实际汇总为 `24 / 24 passed`，MySQL 8.4.7、Java 17.0.18。原始调试输出留在忽略的 tests/member-b/build，版本化报告见 docs/member-b/04_测试报告.md；日志不冒充截图。
